# РЗА | Школа релейной защиты

Публикация учебных постов со схемами и анимациями в https://t.me/rza_school. Go управляет отправкой и историей, Python и Pillow формируют бесплатные учебные иллюстрации.

## Изображения, анимации и редактура

Каждый новый пост автоматически получает схему и оформленную подпись. Оформление версии 3 рассчитано на просмотр с телефона: квадрат 1080×1080, крупные значения, светлый фон и схемы по теме — трансформатор тока, выключатель, зоны защиты, фазоры и временные диаграммы. Для последовательностей действия защиты, логических этапов, симметричного фазорного примера и задач на время создаются шестисекундные MP4-анимации H.264: 120 кадров при 20 кадрах/с, с остановками для чтения этапов. Темп анимации условный, значения берутся из текста задачи. Остальные материалы получают PNG-схему. Подпись структурируется на «Дано», «Решение» и «Вывод» либо на вопрос и разбор; расчёты и единицы сохраняются.

Локальная установка: `python -m pip install -r media/requirements.txt`. Нужен шрифт Arial в Windows или DejaVu Sans в Linux; workflow устанавливает зависимости сам. В пакет imageio-ffmpeg входит локальный кодировщик видео. Пример предпросмотра: `python media/render.py --file posts/lessons/080-auto.txt --output-dir media/generated`. Результат — MP4 или PNG и JSON с подписью и контрольными суммами. Платные API не используются. Кэш учитывает контрольные суммы исходного текста и кода оформления, поэтому изменения стиля не оставляют старые изображения.

Медиа отправляется одним сообщением с подписью, поэтому число публикаций за запуск не меняется. Ограничение подписи Telegram проверяется до отправки; длинные тексты не обрезаются. История сохраняет тип медиа, Telegram file_id, версию оформления и контрольную сумму фактической подписи. Исходные тексты и их контрольные суммы остаются основой очереди.

Уже выпущенные сообщения можно обновить на месте через `media/upgrade.py`: ссылки и номера сообщений сохраняются. Подтверждения каждого редактирования записываются в отдельный JSON; повторный запуск пропускает подтверждённые правки.

Просмотреть первый пост без отправки:

```powershell
go run .
```

Отправить пост из PowerShell в папке проекта:

```powershell
.\publish.ps1
```

Скрипт запросит токен со скрытым вводом и передаст его программе через переменную окружения только на время запуска. Токен не записывается в файл. Бот должен быть администратором канала с правом публикации.

Другой пост: `.\publish.ps1 -PostFile posts/002.txt`. Формат — обычный текст UTF-8, от 1 до 4096 символов. Каждый запуск скрипта создаёт новую публикацию. После сетевой ошибки сначала проверьте канал: Telegram мог принять сообщение.

Для прямого запуска используются переменные `TELEGRAM_BOT_TOKEN` и, при необходимости, `TELEGRAM_CHANNEL` (по умолчанию `@rza_school`): `go run . -file posts/001-welcome.txt -send`.

Проверка: `go test ./...`.

## Запуск в GitHub Actions без ноутбука

Workflow `.github/workflows/publish.yml` запускает очередь каждый час, на 17-й минуте часа по Москве. Каждый обычный запуск последовательно публикует 10 постов. GitHub может задерживать или пропускать запуски при высокой нагрузке. Расписание работает с основной ветки; в публичном репозитории GitHub отключает расписание после 60 дней без активности.

В Settings → Secrets and variables → Actions создайте секрет `TELEGRAM_BOT_TOKEN` с токеном бота канала РЗА. Токен не должен попадать в коммиты. Локальный `.env` читается автоматически, но в репозиторий не загружается. Настройка workflow требует права `contents: write`; защита основной ветки должна разрешать коммиты от workflow.

После добавления секрета откройте Actions → Publish RZA lesson → Run workflow для первого облачного запуска. Он отправит следующие 10 уроков из очереди. Для проверки только пополнения отметьте `Prepare and save lessons without publishing` — уроки сохранятся в репозиторий без отправки в канал. Последующие обычные запуски выполняются по расписанию независимо от ноутбука и Codex.

Очередь находится в `posts/lessons`: файлы `.txt` публикуются в порядке числовых префиксов, каждый — один раз. Первые 6 уроков были подготовлены вручную. Перед каждым запуском программа бесплатно пополняет очередь до 1000 ещё не опубликованных материалов командой `./publisher -prepare -buffer 1000`. Уже отправленные посты в этот запас не входят. Новые файлы сохраняются в репозитории до отправки. Для каждого из десяти постов резервирование сохраняется перед отправкой, а результат — сразу после неё. При ошибке серия останавливается; автоматический повтор неоднозначной отправки заблокирован.

## Бесплатное автоматическое продолжение

Для разовой догоняющей отправки параметр ручного запуска `target_total` задаёт целевое общее число опубликованных учебных постов. Например, при 10 уже отправленных постах и цели 108 программа отправит ещё 98. Число пересчитывается после получения актуального состояния; уже достигнутая цель не вызывает новых отправок. Значение 0 сохраняет обычную серию из 10 постов. Параметр не изменяет часовое расписание. Между отправками предусмотрена пауза не менее секунды; каждая отправка сохраняется отдельно.

Платные API и ключи генеративных моделей не используются. В `content/course.json` подготовлены 24 темы по РЗА: измерительные цепи, токовые и дифференциальные принципы, резервирование, АПВ, АВР и анализ записей. Сначала выходят объяснения с вопросами, затем разборы ситуаций и самопроверка — всего 72 материала.

После курса автоматически создаются расчётные упражнения с новыми исходными данными: пересчёт токов в идеальной модели, сумма времён, интервалы событий, условный баланс токов и перевод единиц. Ответы вычисляются Go-программой. Параметры меняются последовательно; шаблоны упражнений повторяются. Новые теоретические темы программа сама не изобретает. Это сборка материалов подготовленного курса и генератор задач, а не автономный ИИ-автор.

Очередь не требует ручного пополнения для продолжения этих упражнений. Новые теоретические темы можно добавлять в `content/course.json`; порядок и охват курса следует менять с учётом уже выпущенных материалов. Не удаляйте файлы `*-auto.txt`: по ним отслеживается позиция курса. При незавершённой отправке или отсутствующих исходниках опубликованных уроков пополнение останавливается для проверки.

Для локального предпросмотра без Telegram: `go run . -prepare -queue preview/lessons -state preview/state.json`. Посмотреть полученные тексты можно в `preview/lessons`. Источники для сверки основных принципов перечислены в `content/REFERENCES.md`. Материалы и идеализированные задачи не заменяют проектные расчёты и документацию конкретного оборудования.

Состояние хранится в `.publisher-state.json` и коммитится перед отправкой и после неё. Это предотвращает автоматическую повторную отправку после неоднозначной ошибки. Если запуск остановился с `pending` или `attempted`, сначала проверьте канал: если пост уже появился — внесите его `message_id` и статус `sent`; если достоверно не появился — удалите только соответствующую запись для повторного резервирования. Затем запустите workflow вручную. Не удаляйте историю успешных постов.

Локальная проверка очереди без отправки: `go run . -reserve -state queue-preview.json`. Файл предпросмотра не используется workflow и не должен попадать в коммиты.
